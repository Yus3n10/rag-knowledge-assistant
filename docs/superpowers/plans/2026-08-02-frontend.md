# Phase 4b: Frontend — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A web interface where an answer's citations can be clicked open to reveal the exact regulation text they came from.

**Architecture:** React + TypeScript + Vite, talking to the existing FastAPI backend. No server-side rendering, no state library — the app has one screen and one request.

**Tech Stack:** React 18, TypeScript, Vite. No component library, no Redux/Zustand, no react-query.

## Global Constraints

- **The citation view is the deliverable.** Login and layout are commodity work that any bootcamp project has. The thing that demonstrates grounding — and the only thing here a reviewer has not seen a hundred times — is being able to click a citation and read the source paragraph that produced the claim. **Build it first (Task 2), before auth plumbing (Task 3).** If this phase gets cut short, the differentiator must already exist.
- Dependencies: `react`, `react-dom`, `typescript`, `vite`, `@vitejs/plugin-react` and their types. **Nothing else.** No Tailwind, no MUI, no shadcn, no react-query, no axios (`fetch` is built in). This app has one screen; a component library would be more configuration than code.
- The backend is **unchanged** by this phase. If the frontend needs data the API does not return, that is a finding to report, not a licence to edit `api/main.py` mid-task.
- Commit messages carry NO AI/Claude/Anthropic attribution and NO Co-Authored-By trailer.
- Never commit a token or password. The demo credentials belong in the README, not in source.

## Backend contract — already built, do not change

| Endpoint | Shape |
|---|---|
| `POST /auth/login` | `{username, password}` -> `{access_token, token_type}` |
| `POST /ask` | Bearer token; `{question}` -> `answer`, `citations`, `citation_report`, `ungrounded_numbers`, `retrieved`, `stats` |
| `GET /health` | liveness + chunk count |

- `citations` is a list of paragraph ids, e.g. `["1910.147(e)(3)"]`.
- `retrieved` carries paragraph ids with distances.
- Demo users: `viewer` (no roles) and `officer` (role `safety_officer`).
- **Authenticated `/ask` takes ~8 seconds.** That is measured, not a bug. The UI must show a real pending state; a spinner with no explanation will read as broken at that duration.

## A gap to resolve in Task 1, not to paper over

`/ask` returns citation **ids**, but not the **text** of each retrieved chunk. To display source text on click, the frontend needs that text.

Establish in Task 1 which is true, and report it:
- if `retrieved` already includes chunk text, use it;
- if it does not, the honest fix is a backend change — and that belongs in a separate, explicitly-scoped task with its own tests, not smuggled into a frontend commit.

Do not work around a missing field by re-querying, guessing, or displaying the paragraph id alone as though it were the source. The entire point of this screen is showing the actual text.

## Task 2: The citation view ⭐

**Files:** `web/src/components/Answer.tsx`, `web/src/components/Citation.tsx`, tests

This is the phase's reason for existing.

- Render the answer text with each `[1910.147(e)(3)]` citation as an inline, clickable element.
- Clicking expands the source paragraph inline — its id, its heading trail, and its text.
- Cited paragraphs the model referenced are visually distinct from merely-retrieved ones.
- If `ungrounded_numbers` is non-empty, show a visible warning naming the numbers. **Do not hide it.** Surfacing that the system caught its own weak grounding is the honest behaviour and the more impressive one.

- [ ] Build against a **fixture** of the real `/ask` response captured in Task 1 — so this task needs no running backend and no Ollama.
- [ ] Tests: a citation renders as clickable; clicking reveals source text; an answer with no citations renders without crashing; ungrounded numbers produce a visible warning.
- [ ] Commit.

## Task 3: Auth and the ask flow

**Files:** `web/src/App.tsx`, `web/src/api.ts`, tests

- [ ] Login form; store the token in memory (not `localStorage` — this is a demo, and in-memory is both simpler and the safer default to demonstrate).
- [ ] Question input; call `/ask`; render via Task 2's components.
- [ ] Pending state that names what is happening ("Retrieving and generating — this takes a few seconds") rather than a bare spinner, given the measured ~8s.
